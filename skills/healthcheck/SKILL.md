# Brigade 主机加固

## 概述

评估并加固运行 Brigade 的主机，在不破坏访问的前提下使其符合用户定义的风险容忍度。将 Brigade 安全工具作为一等信号，但将操作系统加固视为独立的、明确的步骤集。

## 核心规则

- 建议使用最先进的模型（如 Opus 4.5、GPT 5.2+）运行此技能。Agent 应自检当前模型，若低于该水平则建议切换；不阻止执行。
- 任何改变状态的操作前须获得明确批准。
- 未经确认用户连接方式，不得修改远程访问设置。
- 优先采用可逆、分阶段的变更，并附回滚方案。
- 不得声称 Brigade 会更改主机防火墙、SSH 或操作系统更新；它不会。
- 若角色/身份未知，仅提供建议。
- 格式：每组用户选项必须编号，以便用户回复单个数字。
- 建议进行系统级备份；尽量核实备份状态。

## 工作流（按顺序执行）

### 0) 模型自检（非阻塞）

开始前检查当前模型。若低于最先进水平（如 Opus 4.5、GPT 5.2+），建议切换。不阻止执行。

### 1) 建立上下文（只读）

先尝试从环境推断第 1–5 项，再提问。如需确认，优先使用简单、非技术性问题。

按顺序确定：

1. 操作系统及版本（Linux/macOS/Windows），容器还是主机。
2. 权限级别（root/管理员 vs 普通用户）。
3. 访问路径（本地控制台、SSH、RDP、tailnet）。
4. 网络暴露情况（公网 IP、反向代理、隧道）。
5. Brigade 网关状态及绑定地址。
6. 备份系统及状态（如 Time Machine、系统镜像、快照）。
7. 部署上下文（本地 Mac 应用、无头网关主机、远程网关、容器/CI）。
8. 磁盘加密状态（FileVault/LUKS/BitLocker）。
9. 操作系统自动安全更新状态。
   注意：这些不是阻塞项，但强烈建议检查，尤其是 Brigade 可访问敏感数据时。
10. 具有完全访问权限的个人助手的使用模式（本地工作站 vs 无头/远程 vs 其他）。

先一次性请求运行只读检查的许可。若获准，默认运行，仅对无法推断或验证的项目提问。不要询问运行时或命令输出中已可见的信息。许可请求保持一句话，后续所需信息用无序列表（不编号）列出，除非提供可选项。

若必须提问，使用非技术性提示：

- “你用的是 Mac、Windows PC 还是 Linux？”
- “你是直接在本机登录，还是从另一台电脑连接？”
- “这台机器可从公网访问，还是仅限家庭/局域网？”
- “你启用了备份吗（如 Time Machine），是最新的吗？”
- “磁盘加密开启了吗（FileVault/BitLocker/LUKS）？”
- “自动安全更新开启了吗？”
- “你如何使用这台机器？”
  示例：
  - 与助手共用的个人机器
  - 专供助手使用的本地机器
  - 专供远程访问的专用远程机器/服务器（常开）
  - 其他？

仅在系统上下文明确后再询问风险画像。

若用户授予只读权限，默认运行对应操作系统的检查。若未授予，提供选项（编号）。示例：

1. 操作系统：`uname -a`、`sw_vers`、`cat /etc/os-release`。
2. 监听端口：
   - Linux：`ss -ltnup`（若 `-u` 不支持则用 `ss -ltnp`）。
   - macOS：`lsof -nP -iTCP -sTCP:LISTEN`。
3. 防火墙状态：
   - Linux：`ufw status`、`firewall-cmd --state`、`nft list ruleset`（按已安装的选用）。
   - macOS：`/usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate` 和 `pfctl -s info`。
4. 备份（macOS）：`tmutil status`（若使用 Time Machine）。

### 2) 运行 Brigade 安全审计（只读）

作为默认只读检查的一部分，运行 `brigade security audit --deep`。仅在用户要求时提供替代方案：

1. `brigade security audit`（更快，不探测）
2. `brigade security audit --json`（结构化输出）

提供应用 Brigade 安全默认值的选项（编号）：

1. `brigade security audit --fix`

明确说明 `--fix` 仅收紧 Brigade 默认值和文件权限，不更改主机防火墙、SSH 或操作系统更新策略。

若启用了浏览器控制，建议所有重要账户启用 2FA，优先硬件密钥，短信不够充分。

### 3) 检查 Brigade 版本/更新状态（只读）

作为默认只读检查的一部分，运行 `brigade update status`。

报告当前渠道及是否有可用更新。

### 4) 确定风险容忍度（系统上下文明确后）

请用户选择或确认风险态势及所需开放服务/端口（下方编号选项）。
不要强行归入固定画像；若用户偏好，记录需求而非选择画像。
提供建议画像作为可选默认值（编号）。注意多数用户选择“家庭/工作站均衡”：

1. 家庭/工作站均衡（最常见）：防火墙开启并采用合理默认值，远程访问限制在局域网或 tailnet。
2. VPS 加固：入站防火墙默认拒绝，最小开放端口，仅密钥 SSH，禁止 root 登录，自动安全更新。
3. 开发者便利：允许更多本地服务，明确暴露警告，仍进行审计。
4. 自定义：用户定义的约束（服务、暴露面、更新频率、访问方式）。

### 5) 生成修复计划

提供包含以下内容的计划：

- 目标画像
- 当前态势摘要
- 与目标的差距
- 逐步修复及精确命令
- 访问保持策略与回滚
- 风险及潜在锁定场景
- 最小权限说明（如避免管理员使用，安全处收紧所有权/权限）
- 凭据卫生说明（Brigade 凭据位置，优先磁盘加密）

任何变更前始终先展示计划。

### 6) 提供执行选项

提供以下选项之一（编号，以便用户回复单个数字）：

1. 帮我执行（引导式，逐步批准）
2. 仅展示计划
3. 仅修复关键问题
4. 导出命令供后续使用

### 7) 带确认执行

每一步：

- 展示精确命令
- 说明影响与回滚
- 确认访问仍可用
- 遇意外输出即停止并请求指导

### 8) 验证并报告

重新检查：

- 防火墙状态
- 监听端口
- 远程访问仍可用
- Brigade 安全审计（重新运行）

交付最终态势报告并注明任何延后事项。

## 必需确认（始终）

以下操作须获得明确批准：

- 防火墙规则变更
- 开放/关闭端口
- SSH/RDP 配置变更
- 安装/移除软件包
- 启用/禁用服务
- 用户/组修改
- 调度任务或启动持久化
- 更新策略变更
- 访问敏感文件或凭据

不确定时，询问。

## 定期检查

Brigade 安装或首次加固后，至少运行一次基线审计和版本检查：

- `brigade security audit`
- `brigade security audit --deep`
- `brigade update status`

建议持续监控。使用 Brigade cron 工具/CLI 调度定期审计（Gateway 调度器）。未经明确批准不得创建调度任务。将输出存储在用户批准的位置，避免日志中出现密钥。
调度无头 cron 运行时，在输出中注明提示用户调用 `healthcheck` 以便修复问题。

### 必需的调度提示（始终）

任何审计或加固后，明确提供调度选项并要求直接回复。使用简短提示（编号）：

1. “要我通过 `brigade cron add` 调度定期审计（如每日/每周）吗？”

若用户同意，询问：

- 频率（每日/每周）、首选时间窗口及输出位置
- 是否同时调度 `brigade update status`

使用稳定的 cron 任务名以确保更新确定性。优先使用精确名称：

- `healthcheck:security-audit`
- `healthcheck:update-status`

创建前先 `brigade cron list` 并按精确 `name` 匹配。若已存在，`brigade cron edit <id> ...`。
若不存在，`brigade cron add --name <name> ...`。

同时提供定期版本检查，以便用户决定何时更新（编号）：

1. `brigade update status`（源码检出和渠道首选）
2. `npm view brigade version`（已发布的 npm 版本）

## Brigade 命令准确性

仅使用受支持的命令和标志：

- `brigade security audit [--deep] [--fix] [--json]`
- `brigade status` / `brigade status --deep`
- `brigade health --json`
- `brigade update status`
- `brigade cron add|list|runs|run`

不得杜撰 CLI 标志，或暗示 Brigade 会强制执行主机防火墙/SSH 策略。

## 日志与审计追踪

记录：

- 网关身份与角色
- 计划 ID 与时间戳
- 已批准的步骤及精确命令
- 退出码及修改的文件（尽力而为）

脱敏密钥。绝不记录令牌或完整凭据内容。

## 记忆写入（有条件）

仅在用户明确选择加入且会话为私有/本地工作区时写入记忆文件
（依据 `docs/reference/templates/AGENTS.md`）。否则提供脱敏、可直接粘贴的摘要，由用户
决定是否保存到别处。

遵循 Brigade 压缩使用的持久记忆提示格式：

- 将持久笔记写入 `memory/YYYY-MM-DD.md`。

每次审计/加固后，若已选择加入，向 `memory/YYYY-MM-DD.md` 追加简短的带日期摘要
（检查了什么、关键发现、采取的操作、任何已调度的 cron 任务、关键决策、
以及执行的所有命令）。仅追加：绝不覆盖现有条目。
脱敏敏感主机细节（用户名、主机名、IP、序列号、服务名、令牌）。
若有持久偏好或决策（风险态势、允许端口、更新策略），
同时更新 `MEMORY.md`（长期记忆为可选，仅在私有会话中使用）。

若会话无法写入工作区，请求许可或提供精确条目
供用户粘贴到记忆文件。
